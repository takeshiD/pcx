# Use las-rs with explicit LAS mappings

LAS and LAZ I/O will use the maintained pure-Rust `las` crate with its serial `laz` feature: its MIT-licensed LAS implementation and Apache-2.0-licensed `laz` codec preserve crates.io packaging and native x86_64/aarch64 Linux builds without a C/C++ runtime. The adapter remains synchronous and maps decoded coordinates into the common schema as semantic `f64` X/Y/Z Point Fields while retaining the LAS scale/offset transform and CRS records as spatial metadata; classification components and other standard attributes become explicitly named typed Point Fields, while Extra Bytes become one ordered raw Point Field with their original descriptor records retained for writing. LAZ compression uses serial bounded chunks, and writing rejects unrepresentable fields, metadata, or coordinate quantization unless the caller explicitly authorizes the corresponding loss category under ADR-0002; this decision extends rather than supersedes the existing synchronous, deep-module, fidelity, and memory-bound decisions.
